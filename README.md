# 倉庫 PDA 上架・模擬情境

這是個人作業構想的情境模擬，供交流討論。單一 HTML 的互動原型，重點只有兩個：反覆進出貨物查詢／陳列，以及只完成一項商品就誤關整台車。改善版提供必要數量與整車進度，並硬性阻擋未完成關倉。

沒有統計、儀表板、登入、後端、資料庫、外部 API 或真實庫存資料。

## 開啟與操作

直接用瀏覽器開啟 `index.html`，不需要安裝或建置。全部樣式、程式與 Demo 資料都在此檔案內。

- 上方切換「原作業情境／構想作業情境」，兩模式各自保留進度及已輸入內容。
- 「重新開始目前流程」只重設目前模式；重新整理會重設兩模式。
- 掃碼按鈕代替現場掃碼；需要時可展開「手動輸入條碼」。
- 沒有相機或掃碼硬體存取，也不使用瀏覽器永久儲存。
- 頂端可切換「繁體中文／한국어／English」，預設繁體中文；商品名稱、操作文字、進度與錯誤提示均會翻譯，條碼及儲位代碼維持原值。
- 切換語言不重設兩模式的進度、已輸入數量或當前畫面；重新整理後恢復繁體中文。

### 原作業情境

貨物查詢 → 掃 CART-001 → 查看商品 → 回主選單 → 陳列 → 再掃 CART-001 → 掃商品 → 掃儲位 → 輸入數量 → 上架。

同商品換儲位也要重新掃商品。陳列畫面不顯示累計與剩餘，只提示上架成功。可按「回貨物查詢確認」，再次掃車查詢；泡麵完成後會從查詢清單消失。

再回主選單進陳列、掃車，按「完成／清除」。如果還有飲料與糖果，會顯示誤關整車的風險；Demo 保留資料，能繼續操作。

### 構想作業情境

陳列 → 掃車 → 本車商品 → 開始上架 → 掃商品 → 掃儲位 → 輸入數量 → 上架。

上架後立即更新總數、已上架與剩餘，同商品可直接掃下一儲位。整車進度保持可見。

「完成商品車」刻意保留可點擊，讓觀看者直接體驗防呆。只要還有剩餘商品，完成處理函式會阻擋並列出未完成項目；沒有「仍要完成」或 Yes／No 的繞過選項。全部上架後才會真正進入完成畫面。

## 上傳 GitHub 與發布

1. 建立一個 GitHub 公開儲存庫，例如 `pda-demo`。
2. 將此資料夾內的 **`index.html`、`README.md`** 上傳至儲存庫根目錄；不必上傳工作區其他資料、測試程式或截圖。
3. 打開儲存庫 **Settings → Pages**。
4. 在 **Build and deployment → Source** 選 **Deploy from a branch**。
5. 在 **Branch** 選 **main**，資料夾選 **/(root)**，按 **Save**。
6. 等待發布完成，回到 Pages 查看網站連結；若發布失敗，在儲存庫 Actions 查看紀錄。

網址形式：`https://<GitHub帳號>.github.io/<儲存庫名稱>/`。

例如帳號 `demo-user`、儲存庫 `pda-demo`，網址就是 `https://demo-user.github.io/pda-demo/`。此為格式示例，並非已發布連結。

[GitHub Pages 官方發布來源設定說明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

本 Demo 沒有 localhost 路徑或外部資源，也沒有需要伺服器轉送的路由，可部署在儲存庫子路徑。尚未連結 GitHub 儲存庫，交付時未實際發布。

## 手機操作確認

發布後，用手機 Safari 或 Chrome 開啟 Pages 網址，確認：

1. 直向畫面不需左右滑動；模擬掃碼按鈕可點。
2. 輸入數量時鍵盤可正常開啟，捲動後可點「上架」。
3. 原作業情境做完泡麵後，回查詢只剩飲料與糖果。
4. 構想作業情境在 1／3 完成時，按「完成商品車」會被阻擋。
5. 飲料與糖果也上完後，可以正常完成商品車。
6. 切換分頁仍保留各模式進度；重新開始只影響目前模式。

本機 HTML 可完全離線執行。手機是否能直接開啟下載的 HTML，取決於系統及瀏覽器；手機分享建議使用 Pages 網址。沒有 Service Worker，不保證離線重新開啟網址。
